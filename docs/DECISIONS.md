# DECISIONS — журнал решений

Формат: контекст → решение → последствия. Приоритет источников: «Дополнения к ТЗ» > «ТЗ» > постановка хакатона.

## D-001. Прейскурант на сайте
- **Контекст:** ТЗ §5.4 относит «прейскуранты» к тому, что не входит в состав сайта. «Дополнения» §1 и §9 прямо разрешают публиковать постановление и утверждённый прейскурант как справочную информацию.
- **Решение:** следуем «Дополнениям». Раздел «Платные услуги» публикует постановление (PDF, каз/рус) и таблицу прейскуранта. Нет: расчёта стоимости, количества, корзины, кнопок «заказать/оплатить». Постоянный баннер «Оформление и оплата на этом сайте не производятся».

## D-002. Исходные `seed/branches.json` и `seed/memorial_dates.json` отсутствовали
- **Контекст:** постановка ссылается на готовые JSON, но заказчик передал XLS («Адреса и контакты филиалов.xls») и 5 DOCX-календарей.
- **Решение:** JSON генерируются воспроизводимыми скриптами из `seed/tools/` по файлам в `docs/source/`. Координаты проставлены вручную по центрам населённых пунктов (приблизительно), `coords_verified=false` у всех; у двух филиалов (Маркаколь, Тарбагатай/Акжар) — `null`, т.к. населённый пункт неоднозначен. В UI — бейдж «Координаты не подтверждены».

## D-003. Персональные данные
- Каталог: только синтетические записи и вымышленные/обезличенные персоналии; бейдж «Демонстрационная запись».
- «Об архиве», «Структура», «Контакты», филиалы: служебные ФИО/телефоны/e-mail руководителей взяты из материалов заказчика (они опубликованы на действующем сайте). Это служебная, а не личная информация; в каталог и ИИ-контекст не попадают.

## D-004. Публичная видимость записи каталога
- Две независимые оси: `description_status` (public | hidden | review) — можно ли показывать **описание**; `file_access` (open | restricted | closed) — можно ли выдавать **цифровую копию**.
- Третья ось — редакционный `workflow_status` (draft … published, archived).
- **Карточка видна публично** ⇔ `description_status='public'` И `workflow_status='published'`. Иначе — 404 (не раскрываем существование).
- **Файл выдаётся** ⇔ карточка видна И `file_access='open'` И файл помечен `is_public_copy`. Иначе 403 (если карточка видна) / 404.
- Любое значение вне перечня или NULL трактуется как закрытое (CHECK-ограничения в БД + `deny-by-default` в коде).

## D-005. Кейс ИИ «запрос к закрытому материалу»
- Закрытые записи не попадают ни в FTS-индекс, ни в контекст LLM. Чтобы ответить «материал может существовать, но доступ ограничен», используется отдельный **агрегированный** признак: в публичной карточке фонда/дела может стоять `restricted_note` (например, «дела по личному составу 1950–1970 — ограниченный доступ»), а ИИ дополнительно распознаёт по ключевым словам темы ограниченного доступа (личные дела, судебные/следственные дела, медицинские сведения, документы по личному составу < 75 лет). Ответ не содержит ни шифров, ни названий закрытых дел.
- Карточки с `description_status='public'` и `file_access='closed'` ИИ показывает как источник **с пометкой «доступ ограничен»**, без файла.

## D-006. Поиск: PostgreSQL FTS вместо Elasticsearch
- Причины: один сервис меньше (важно для гос-инфраструктуры и 36 ч), транзакционная согласованность индекса и статуса доступа, `pg_trgm` для опечаток, `unaccent`, конфиги `russian` + `simple` для kk/en.
- Индекс — отдельная таблица `search_index`, заполняется **только** для видимых публично записей (D-004). Доступ — через интерфейс `SearchBackend`; замена на OpenSearch — новая реализация того же интерфейса + outbox-синхронизация (описано в ARCHITECTURE.md).

## D-007. Локальная среда без Docker
- На машине разработки нет Docker/WSL/make. Каноничный запуск — `docker compose` (`make up`). Для локальной разработки на Windows — `scripts/dev.py` (те же цели: `up`, `seed`, `test`, `lint`), PostgreSQL 16 — локальный сервер. Makefile — тонкая обёртка над теми же командами.

## D-008. Идентификаторы
- Суррогатные UUID для всех сущностей; в URL публичных карточек — UUID (устойчив, не зависит от названия). Шифр (`cipher`) — отдельная строка с уникальностью, используется для дедупа импорта.

## D-009. Переводы
- Переводимые поля вынесены в `<entity>_translations(entity_id, lang, …, translation_status)`; `translation_status ∈ {original, verified, machine, missing}`.
- Если перевода на запрошенный язык нет или он `missing` — API отдаёт оригинал и флаг `fallback_lang`, UI показывает «Перевод отсутствует, показан оригинал (рус.)». `machine` помечается «Машинный перевод, не проверен».

## D-010. Сессия админки
- JWT (HS256, секрет из env) в httpOnly + Secure + SameSite=Strict cookie, срок 30 мин со скольжением (автологаут по неактивности). CSRF — double-submit: cookie `csrf_token` (не httpOnly) + заголовок `X-CSRF-Token` на всех небезопасных методах.

## D-011. Публичный рейтинг/счётчик, погода, опрос, лента соцсетей
- «Дополнения» делают их условными («если подтвердит заказчик»). Подтверждения нет → реализуем как явно помеченные справочные ссылки/плейсхолдеры; ленту соцсетей не тянем (нет официального API без ключей), показываем кнопки-ссылки.

## D-012. Прейскурант — выписка, набранная по скану
- **Контекст:** PDF постановления № 289 от 15.12.2023 — скан без текстового слоя (15 стр.).
- **Решение:** разделы 6 (запросы, справки) и 8 (копии) набраны вручную по скану в `seed/content/price_list.json` и показаны таблицей; остальные разделы — перечнем со ссылкой на страницы PDF. На странице пометка «набрано по скану — юридическую силу имеет текст постановления». Оба PDF (рус/каз) доступны для скачивания. Никаких расчётов стоимости.

## D-013. Ссылки на нормативные акты
- Прямые ссылки на «Әділет» сформированы по реквизитам актов и помечены `verified=false` («ссылка не подтверждена заказчиком»). Для актов, у которых регистрационный номер неизвестен, — ссылка на главную «Әділет» с пометкой «найдите по реквизитам». Выдумывать идентификаторы документов нельзя.

## D-014. Ограничение частоты запросов
- `slowapi`-декоратор конфликтует с `from __future__ import annotations` (FastAPI не видит модель тела). Используем ядро slowapi — библиотеку `limits` (moving window, in-memory) в виде зависимости FastAPI `rate_limit(spec, scope)`. Для нескольких воркеров — Redis-хранилище `limits`.

## D-015. Официальные документы на справочных страницах
- PDF комплаенс-службы и постановления отдаются эндпоинтом `/api/public-docs/{key}` строго по белому списку ключей (`app/cms/public_docs.py`). Это не сканы каталога; каталог по-прежнему только через `/api/media` с проверкой доступа.

## D-016. Демонстрационные тексты
- Тексты без источника у заказчика («Миссия», «Госуслуга», «Читальный зал», «Политика конфиденциальности») помечены `is_demo` — в UI бейдж «Демонстрационная запись» и строка «требует утверждения заказчиком». Раздел «Отчёты» оставлен незаполненным с объяснением (Д §9).

## D-017. Правка опубликованного материала
- Пользователь без права `content.publish` (редактор, архивист), изменяя материал в статусе «На проверке / Одобрено / Опубликовано», возвращает его в «На проверке» — материал снимается с сайта до повторного согласования. Модератор/администратор правит опубликованное без смены статуса; каждая правка — новая версия в `content_versions`.
- Альтернатива (черновик-ревизия поверх опубликованной версии) отложена: требует хранения двух редакций одновременно.

## D-018. Принцип четырёх глаз
- Нельзя одобрить/опубликовать/вернуть материал, который ты сам отправил на проверку (кроме superadmin для аварийных случаев). Попытка фиксируется в журнале как `denied`.

## D-019. Публикация записи каталога и статусы доступа
- Переход документа (фонда/описи/дела) в «Опубликовано» переводит описание из «Требует проверки» в «Публично»; описание «Не публиковать» не меняется (с предупреждением). Доступ к цифровой копии (`file_access`) workflow не меняет никогда — только отдельная операция с правом `catalog.set_access` и обязательным основанием, которое пишется в журнал.
- Новая запись создаётся «закрытой» по умолчанию: draft / review / closed.

## D-020. Язык админ-панели
- Интерфейс админки — на русском (рабочий язык сотрудников для прототипа). Контент редактируется на трёх языках через вкладки KK/RU/EN; правка перевода человеком ставит статус `verified`.
